Setup & Configuration

This section walks you through downloading, installing, and configuring the project from scratch. No prior experience with Python or MCP is required — just follow each step in order.

1 Download the Project

Go to the GitHub repository in your web browser:

https://github.ibm.com/Ahmed-Elpannann/Bob-A-Thon-2026-Spec-Driven

Click the green "Code" button, then click "Download ZIP". Save the file to your computer (e.g., your Desktop or Downloads folder).

Once downloaded, right-click the ZIP file and select "Extract All..." (Windows) or double-click it (Mac). This creates a folder called Bob-A-Thon-2026-Spec-Driven-main.

2 Install Python (if not already installed)

Open a terminal (Command Prompt on Windows, Terminal on Mac) and type:

python --version

If you see Python 3.11 or higher, you are good. If not, download Python from:

https://www.python.org/downloads/

Important: During installation on Windows, check the box that says "Add Python to PATH".

3 Install the Required Packages

Open a terminal and navigate to the project folder you extracted:

cd Desktop/Bob-A-Thon-2026-Spec-Driven-main

Then install the dependencies:

pip install -e .

This installs the MCP server and all its dependencies (fastmcp, pydantic, etc.). You only need to do this once.

4 Verify the Installation

Run the test suite to confirm everything works:

python -m pytest tests/ -v

You should see 81 tests passed in green. If any test fails, check that Python 3.11+ is installed and try pip install -e . again.

5 Open the Project in VS Code

Open VS Code, then click File → Open Folder and select the Bob-A-Thon-2026-Spec-Driven-main folder.

Bob (the IBM AI assistant) will automatically detect the .bob/mcp.json file in the project and connect to the MCP server.

6 Start the MCP Server

The MCP server starts automatically when Bob detects the .bob/mcp.json configuration. If you need to start it manually for testing:

uvx fastmcp run src/universal_spec_mcp/server.py

You should see: Universal Spec Architect running on stdio

7 Select the BMad Mode in Bob

In the Bob chat panel (bottom of VS Code), click the mode selector and choose "BMad Spec Architect". Bob will confirm:

Bob
BMad Spec Architect mode activated. I have loaded four specialist skills: Analyst (Mary), Architect (Winston), PM (John), and Developer (Amelia). Tell me what feature you want to build.

Troubleshooting

  • Bob doesn't show the mode: Make sure the .bob/ folder is in the root of the project you opened.
  • "Module not found" error: Run pip install -e . again from the project folder.
  • MCP server won't start: Check that uvx is installed: pip install uv
  • Tests fail: Ensure Python 3.11+ with python --version

Overview

Making Bob Think Before It Codes

AI coding assistants are powerful — but by default, they are reactive. When asked to build a feature, they immediately start writing code. In an enterprise environment, this leads to undocumented decisions, missed edge cases, and code that is difficult to maintain or audit. The Universal Spec MCP server solves this by inserting a structured engineering workflow before any code is written. It forces the AI to document requirements, produce a design, and break the work into tasks — ensuring that every line of code is traceable back to an approved specification.

Workflow Architecture

The system operates across four distinct layers:

  • You (The Developer): You provide the initial idea and answer clarifying questions.
  • BMad Agents: Four specialized personas (Mary, Winston, John, Amelia) guide the conversation and execute specific phases of the workflow.
  • MCP Server: A Python backend that exposes 25 tools to the agents, enforcing rules like EARS notation validation and privacy filtering.
  • Project Repository: The .specs/ directory where all requirements, designs, and tasks are saved as versioned Markdown files.

Step 2.2

Design Produced

Winston (Architect)
Based on the requirements, here is my proposed design:

Data Model: New password_reset_tokens table with columns: id, user_id, token_hash, created_at, used_at.

Sequence: POST /reset-request → validate email → generate token → hash with SHA-256 → store → send via SendGrid → user clicks link → GET /reset/:token → validate expiry → show form → POST /reset/:token → validate password → update user → delete token → redirect.

ADR-001: Token Storage Strategy
Decision: Store SHA-256 hash of token, not plaintext.
Rationale: If the database is compromised, attackers cannot use stolen tokens. The token is only sent in the email — the server never stores the raw value.
Alternatives considered: (1) Store plaintext — rejected due to security risk. (2) Encrypt with AES — rejected as unnecessary complexity when hashing is sufficient.

import secrets, hashlib
from sendgrid import SendGridAPIClient
from sendgrid.helpers.mail import Mail

@app.post("/api/reset-request")
async def reset_request(email: str):
    user = await db.get_user_by_email(email)
    if not user:
        return {"message": "If that email exists, a reset link was sent."}

    token = secrets.token_hex(32)  # 64-char hex string
    token_hash = hashlib.sha256(token.encode()).hexdigest()

    await db.insert_reset_token(user.id, token_hash)

    link = f"https://app.example.com/reset/{token}"
    msg = Mail(to_emails=email, subject="Password Reset",
               html_content=f'<a href="{link}">Reset your password</a>')
    SendGridAPIClient(SENDGRID_KEY).send(msg)

    return {"message": "If that email exists, a reset link was sent."}

import re
from datetime import datetime, timedelta

@app.get("/reset/{token}")
async def validate_token(token: str):
    token_hash = hashlib.sha256(token.encode()).hexdigest()
    record = await db.get_reset_token(token_hash)

    if not record:
        raise HTTPException(404, "Invalid reset link.")
    if datetime.utcnow() - record.created_at > timedelta(minutes=15):
        await db.delete_reset_token(token_hash)
        raise HTTPException(410, "This reset link has expired. Please request a new one.")

    return render_template("reset_form.html", token=token)

@app.post("/reset/{token}")
async def reset_password(token: str, password: str, confirm: str):
    if password != confirm:
        raise HTTPException(400, "Passwords do not match.")
    if len(password) < 12 or not re.search(r'\d', password) or not re.search(r'[!@#$%^&*()]', password):
        raise HTTPException(400, "Password must be 12+ chars with a number and symbol.")

    token_hash = hashlib.sha256(token.encode()).hexdigest()
    record = await db.get_reset_token(token_hash)
    if not record or datetime.utcnow() - record.created_at > timedelta(minutes=15):
        raise HTTPException(410, "Token expired.")

    await db.update_user_password(record.user_id, hash_password(password))
    await db.delete_reset_token(token_hash)

    return RedirectResponse("/login?msg=Password+updated+successfully", status_code=302)

Follow the recommendation exactly. Do not skip phases or documents that are missing — the MCP server will reject the attempt with a phase gate error.

Key Principles

  • No code without a spec. The MCP server enforces this structurally — you cannot skip phases.
  • Every decision is documented. ADRs, EARS requirements, and task acceptance criteria create a full audit trail.
  • Privacy is automatic. API keys and secrets are redacted before they reach disk.
  • Memory persists. Decisions stored via store_memory are available in future sessions.
